# «Этажом ниже» — прототип заказа еды для фитнес-клуба

Интерактивный прототип сервиса: клиент фитнес-клуба сканирует QR-код в зале, заказывает еду из кафе этажом ниже к нужному времени и идёт тренироваться. Кухня готовит по задачам планировщика, официант относит еду в ячейку шкафа, напиток — на стойку ресепшена. Забрать заказ можно и в самом кафе.

Весь прототип — один файл `index.html` без сервера и сборки: его можно открыть в браузере или выложить на GitHub Pages.

## Приложения

Переключаются панелью вверху страницы или по ссылкам:

| Приложение | Ссылка | Что внутри |
| --- | --- | --- |
| Клиент | `#menu` | 128 позиций по целям питания, 47 напитков, минимальное время готовности, выбор «наверху» или «в кафе», онлайн-оплата (имитация), номер заказа и QR-код для ячейки |
| Кухня | `#kitchen` | задачи планировщика по цехам, график загрузки на час вперёд, упаковка |
| Официант | `#waiter` | рейсы наверх, свободная ячейка и одноразовый QR-код, напитки на стойку, выдача в кафе |
| Шкаф | `#locker` | табло со «сканером» и 12 ячеек трёх размеров |
| Управляющий | `#admin-menu` | меню и акции, склад, закупки, сводка, настройки цехов |
| QR в зале | `#poster` | плакат с QR-кодом, который открывает сайт |

## Как выложить на GitHub Pages

1. На github.com нажмите **New repository**, назовите его, например, `etazhom-nizhe`, выберите **Public** и создайте репозиторий.
2. На странице репозитория нажмите **uploading an existing file** и перетащите туда все файлы и папки из этого архива. Нажмите **Commit changes**.
3. Откройте **Settings → Pages**. В блоке **Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/ (root)`, нажмите **Save**.
4. Через 1–2 минуты сайт откроется по адресу `https://<ваш-логин>.github.io/etazhom-nizhe/`.

Если удобнее через git:

```bash
git clone https://github.com/<ваш-логин>/etazhom-nizhe.git
cd etazhom-nizhe
# скопируйте сюда файлы из архива
git add .
git commit -m "Прототип «Этажом ниже»"
git push
```

GitHub Pages бесплатно работает для публичных репозиториев; для приватного нужен платный тариф GitHub.

## Где хранятся данные

- Данные (меню, склад, заказы, ячейки) хранятся в браузере — в `localStorage`.
- Вкладки одного браузера синхронизируются между собой: откройте «Клиента» в одной вкладке и «Кухню» в другой — новый заказ сразу появится на кухне.
- **Разные устройства данные не делят.** Заказ с телефона не появится на планшете кухни: для этого нужен сервер или облачная база (например, Supabase или Firebase). В версии на claude.ai эту роль играет общая база артефакта.
- Кнопка «Сбросить демо» вверху возвращает исходные демо-данные.

## Ограничения прототипа

- Оплата — имитация, деньги не списываются.
- Камера для сканирования QR в браузере не используется: «поднести телефон к табло» можно кнопкой. QR-коды при этом настоящие, их читает любой сканер.
- История продаж за 4 недели сгенерирована по модели спроса; поставщики, цены и остатки условные.

## Как устроен код

```
index.html        — собранный прототип (всё в одном файле)
build.py          — собирает index.html из src/
src/
  styles.css      — стили
  qrlib.js        — генератор QR-кодов qrcode-generator (MIT, Kazuhiko Arase)
  data.js         — цели, типы, поставщики, ингредиенты, блюда
  data_more.js    — расширение меню и напитки
  core.js         — хранилище, расчёт остатков, прогноз, планировщик, ячейки
  client.js       — сайт клиента
  staff.js        — кухня, официант, шкаф, QR-плакат
  admin.js        — приложение управляющего
  app.js          — маршруты и обработчики действий
```

После правок в `src/` пересоберите прототип командой `python3 build.py` — файл `index.html` в корне обновится.
